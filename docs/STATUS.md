# Status

## How to run

- `npm run dev` — starts the backend (http://127.0.0.1:8000) and the frontend (http://localhost:5173) together; open the frontend and you land on the dashboard.
- `npm test` — backend (pytest), frontend (Vitest) and e2e (Playwright) together; tests run on their own database.
- `npm run seed` — rebuilds the sample data, asking for confirmation before wiping anything.
- `npm run check` — every gate at once: Prettier, ESLint (TypeScript, React Hooks, accessibility), ruff format + check, complexity ≤ 15 per function, `tsc` + `ty`, gitleaks, and `npm test` with unit coverage ≥ 80%; fails if any of them fails. `npm run check:quick` is the same without e2e, `npm run format` fixes formatting, `npm run lint` runs just the static checks.

## Review against main (2026-11-14)

A review of the branch against `main` following `docs/REVIEW.md` — separate bugs, security and spec/plan passes, style excluded. Findings and their fixes:

**Important**

1. **Deleting a contact stranded its deals.** `deals.contact_id` kept pointing at the removed contact (SQLite foreign keys are not enforced), so `PUT /api/deals/{id}` answered `400 Contact does not exist` and the deal could not be saved again. Fixed: deleting a contact (or an organization's contacts) clears the link on any deal that keeps it, the deal form's Contact is optional ("None") like the contact form's Organization, and startup repairs links left dangling by earlier versions. Tests: `test_cascade.py`.
2. **Changing a stage in the edit dialog was a silent, half move.** `PUT /api/deals/{id}` changed the stage but wrote no `stage_change` timeline entry and kept the old column's position. Fixed: a stage change on update now behaves like `POST /deals/{id}/stage` — the new stage's default probability, a slot at the end of the new column, both columns renumbered, and a "Moved from X to Y" entry. Tests: `test_stage_move.py`.
3. **A won deal with a future close date vanished from the dashboard.** `won_summary` dropped `close_date > today`, and Won deals are excluded from the pipeline, so winning a deal before its expected close date showed it on no figure at all. Fixed: close dates are capped at today when bucketing, so the deal counts in the current month. Tests: `test_dashboard.py`.
4. **Contacts accepted a nonexistent organization.** `POST/PUT /api/contacts` wrote `organization_id` values pointing at nothing, while deals and activities validated their links. Fixed: `400 Organization does not exist`, through one shared `require_exists` helper (`app/routes/common.py`); startup also clears links already dangling. Tests: `test_crud.py`, `test_seed.py`.
5. **`opencode.jsonc` widened shell permissions** from `ask` to `allow`, unrelated to the product. Fixed: reverted to `ask`.

**Nits**

1. The cascade dialog keyed list items by their text, so two records sharing a name or description raised a React duplicate-key console error (intent criterion 8: no console errors). Fixed: keyed by group and position.
2. `docs/spec.md`, `docs/changes/mvp/plan.md` and `docs/TECH_STACK.md` all say the e2e suite runs "on installed Chrome", but `playwright.config.ts` silently used Playwright's bundled Chromium — and this machine has no Chrome and no passwordless sudo to install it. Fixed: the config now asks Playwright for `channel: "chrome"` and only falls back to bundled Chromium on Linux when Chrome is absent at Playwright's expected path, so the docs hold everywhere Chrome is installed as `course/SETUP.md` requires.
3. `docs/changes/mvp/plan.md`'s file list had drifted from the build (it listed `src/components/charts/`; the real files include `DealForm.tsx`, `Timeline.tsx`, `lib/charts.ts`, `lib/cascade.ts`, `lib/activity.ts`, `lib/text.ts`, `e2e/helpers.ts`). Fixed: plan updated to the real layout.
4. Delete endpoints returned cascaded names but no counts, where the spec says "the counts and names of cascaded records". Fixed: every delete response carries a `counts` map, asserted in `test_cascade.py`.
5. A failed pipeline drag was only logged to the browser console. Fixed: the board shows a visible, neutral error line until the next successful move.

## Hooks (2026-11-15)

- **Lefthook pre-commit** (`lefthook.yml`; `lefthook` dev dependency installed by the new `prepare` script, so `npm install` wires the git hook): jobs run sequentially — format the staged files (Prettier and ruff format, both with `stage_fixed` so the formatted text is what gets committed), then ESLint/ruff check on the staged files, `tsc`/`ty` over the projects, and `gitleaks git --pre-commit --staged`. Tests are skipped, so a commit takes about 44s. `glob_matcher: doublestar` because the default matcher does not match root-level files with `**/`.
- **Turn-end check** (`plugins/hooks/`, registered in `opencode.jsonc` with a `checkCommand` option, default `npm run check:quick`): on `session.execution.succeeded` — the turn-finished signal, because `session.idle` is in the event schema but never emitted (see findings below) — for a root session of this location, run the check (15-minute timeout, process-group kill). On failure the output tail comes back to the session as a synthetic message so the agent fixes it — at most one per user prompt (a `prompt` hook resets the flag, a passing run clears it), so it blocks once and then lets the agent stop instead of looping. Subagent turns and trees unchanged since the last passing check are skipped, and only one check runs at a time. Failed or interrupted turns emit their own execution events, so they never trigger a check.
- **`.env` protection** (same plugin): a permission `evaluate` hook denying `edit` actions on `.env` / `.env.*` — the committed templates `.env.example`, `.env.sample`, `.env.template` stay editable — and denying shell writes to them (redirects, `tee`, `rm`/`mv`, `sed -i`, `cp` with an `.env` destination). The shell side is pattern matching on the scanner's command text, not a shell parser.
- Tested: lefthook through seven commit scenarios — a badly formatted file committed with the formatted blob (`stage_fixed`), an unused variable, a `tsc` error, a `ty` error and a planted high-entropy secret each blocking the commit with exit 1 and HEAD unchanged, plus a staged deletion and a prettier-ignored `docs/*.md` file committing fine and an empty commit skipping every job. `.env` protection via `write` to `.env` (denied), `echo > .env` (denied as a whole compound command) and `write` to `.env.example` (allowed), all visible in `logs/hooks.log`. The turn-end hook was driven across turns through `checkCommand`: a failing run came back to the agent as a synthetic message it then fixed; a read-only fixture session proved the block-once guarantee in one log (`injected` at 22:24:49, then `suppressed ... already sent one failure this round` at 22:27:06); a failed execution and subagent turns triggered no check; and with `npm run check:quick` restored, the turn-end run passed in 142s (`check pass` in `logs/hooks.log`).
- Two findings from testing: gitleaks' `dir` scan does not respect `.gitignore`, so `logs/hooks.log` must never hold raw shell command text — a logged secret breaks `npm run secrets` (caught and fixed: the log records action/effect and counts, file paths only for `edit`/`read`); and a planted secret must be high-entropy, because gitleaks' `aws-access-token` rule has `entropy = 3` and a `FAKEFAKEFAKEFAKE` repetition scores 2.0 and is silently ignored.
- A third finding, from debugging the turn-end hook: `session.idle` appears in the event schema and the subscription filter but is never emitted by OpenCode 2.3.0 — an unfiltered subscription saw 30 other event types stream past while `session.idle` never appeared, which is why the first version of the hook never fired. The turn-finished signal that does fire, exactly once per completed turn (not per model round), is `session.execution.succeeded`.
